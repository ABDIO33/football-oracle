╔═══════════════════════════════════════════════════════════════════╗
║           ETERNAL HARVEST MASTER — SELF-HEALING DAEMON          ║

▶ EVERY 30 SECONDS:
  1. Check all harvester PIDs in harvest_tracker
  2. Any crashed? → auto-restart with backoff (1min, 2min, 4min... 1hr max)
  3. Any hung (no progress >5min)? → kill + restart
  4. Update health dashboard

▶ EVERY 60 SECONDS:
  1. Check DB growth rate per source
  2. Detect stalls (0 bytes/min for active source)
  3. Log per-source status to eternal_harvest.log

▶ EVERY 5 MINUTES:
  1. Rate limit budget check (reset quotas)
  2. Proxy pool health check
  3. Rotate identities for active harvesters
  4. Check disk space (alert if <10GB free)

▶ EVERY 30 MINUTES:
  1. Check all API keys still valid
  2. Test sample requests to all sources
  3. Report any source failures
  4. Consolidated progress report

▶ EVERY 2 HOURS:
  1. Run feature engineering pipeline (if new data)
  2. Run model training (if enough new data)
  3. Update champion ensemble
  4. Run live predictions

▶ ON FAILURE:
  1. Log full error + traceback
  2. Increment consecutive_failures in harvest_tracker
  3. If failures > max_consecutive_failures:
     - Try alternate proxy tier
     - Try alternate identity
     - If still failing: mark source as "degraded", alert
  4. Auto-retry with exponential backoff
  5. After successful retry: reset counter, log recovery

▶ DASHBOARD (Streamlit):
  - Live harvest progress per source
  - DB growth charts
  - Rate limit remaining
  - Error heatmap
  - Predictions dashboard
  - Training progress
  - Model performance (exact%, 1X2%, RPS)
